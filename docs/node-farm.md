# Node Farm

An original idle incremental game at `/creations/games/node-farm`, in the Games hub's Incremental section. Theme: you hack
one node from a naOS terminal and grow it into a farm. Saves in the browser (`localStorage` key `nf-save-v1`).

## The chain
Bytes (per second) <- Multipliers <- Reboots <- Copper <- Silicon <- Quartz <- Aether <- Runes <- Starglass <- Voidsteel <- Chrono. Every stat except Bytes has six
button tiers (+1, +5, +25, +125, +625, +3125; each tier costs about 8 to 10 times the last, and a button's price grows 9 to 12 percent each time it is bought).
- Multipliers (paid in Bytes) add straight to Bytes per second.
- Reboots (paid in Multipliers) reset Bytes and Multipliers and make every Multiplier button hit harder.
- Copper, Silicon, Quartz and Aether are producers: their buttons add nodes that mine the stat every second. Copper is paid
  in Bytes, each later material in the one before it. Each material boosts the one below it (Copper boosts Reboot power and
  adds a little to Bytes, Silicon boosts Copper, Quartz boosts Silicon, Aether boosts Quartz).
- Runes, Starglass, Voidsteel and Chrono are the deep materials (unlock at 150 Aether, 200 Runes, 250 Starglass, 300 Voidsteel; a quarter of that after your first Ascend). Same rules as the others, each boosts the one below, Chrono adds a little to everything. They also add to the AP you earn (`TUNE.apPer`).
- Prestige tree (see "Prestige tree" below): 40 nodes in five sections, bought with AP, kept through Ascend. `state.tree` holds owned ids; old saves are refunded for nodes that no longer exist.
- Ascend (400 Aether): wipes everything except goals, perks and lifetime stats for Ascension Points (+30 percent to everything each) and five perks.
- There is no tapping: progress comes from buttons only (Nate did not want a Cookie Clicker). The core is a live display: its outer arc shows progress to the cheapest Reboot and it pulses on every press. Quick-time events (see below) appear every 3 to 5 minutes; clearing one gives a x6 Overclock for 20 s.
- Offline progress is capped at 8 hours (Standby cells perk: +4 h per level). Nothing is auto-bought. Returning after more than a minute away opens a full-screen standby report (components/nodefarm/away.tsx): time banked, a standby-window meter, what each resource gained, and a Collect button. Everything is already banked when it opens; Esc or Collect closes it.

## Files
- `lib/nodefarm/engine.ts`: pure rules and every tuning number (`TUNE`). No imports, so the sim runs it in Node.
- `scripts/nodefarm/sim.mjs`: greedy-bot pacing sim. `node --experimental-strip-types scripts/nodefarm/sim.mjs 400`. The bot also ascends and buys tree nodes. Targets Nate picked 2026-11-11: first Ascend about 3 h non-stop, Chrono about 25 h, full tree about 60 h (about a week casual; a casual player is two to three times slower). Last run without Drones: first Reboot 0.04 h, Copper 0.3 h, Silicon 0.5 h, Quartz 0.9 h, Aether 1.9 h, first Ascend 3.3 h, Chrono 24.9 h, tree 59 h. `NF_NODRONES=1` skips the Drones; with the bot arming every stat the first Ascend is 4.8 h and the tree 86 h (it spends Aether on Drones and presses with no reserve), so the truth for a real player sits between. `NF_TUNE='{"perProducer":{"copper":0.06}}'` deep-merges over `TUNE` to try numbers without editing. AP grows with amount^`apPow` (0.3); at 0.5 Ascends snowballed once the early game was fast. Tree costs are doubled from the first version. Change `TUNE`, re-run, compare.
- `components/nodefarm/`: `node-farm.tsx` (game loop at 10 Hz on real elapsed time, UI), `core.tsx` (144 px canvas shown pixelated), `icon.tsx`.
- `app/camino/nodefarm.css`: all styles, scoped under `.ctos .nf`. This is the only naOS surface that uses more than the cyan accent; each stat has its own colour (`--c`).
- `scripts/naos-art/nodefarm-icons.py`: draws the 15 colour 32 px icons (`public/naos/nodefarm/icons.{png,webp}`). Cell order is shared with `components/nodefarm/icon.tsx`.
- Tier icons: every button tier of Multipliers, Reboots and the eight materials has its own 32 px sprite (`public/naos/nodefarm/tiers.{png,webp}`, 6 rows by 6 columns), drawn by `scripts/naos-art/nodefarm-tier-icons.py` and shown by `NfTierIcon` in `components/nodefarm/icon.tsx`. To give a new stat icons, add a `(canvas, tier)` function to `ROWS` in the script and the same id to `TIER_ROWS` in icon.tsx.
- Animated sprites: `scripts/naos-art/nodefarm-sprites.py` turns the static icons and tier icons into four-frame loops (`icons-anim`, `tiers-anim`) and draws the six Drones (`drones`). CSS steps the frames down the sheet (`nfFrame`, `nfTierFrame`, `nfDroneFrame` at the end of nodefarm.css); tier icons only run once the button is affordable. Rarity colours per button tier are `--rar` on `.nf-btn[data-tier]`. Per-Drone colours are in `drones.tsx`. Re-run the script after changing any icon art.
- Core stages (`core.tsx`): hexagon until 4 stats are unlocked, then an octagon with an inner rotor, then an eight-pointed crystal at 6 stats. Layers on top: an orbiting node per unlocked stat past the second, a centre spoke per doubling of Reboots (max 8), and a halo segment per Ascension Point (max 24).
- Sounds: the `nf*` entries in `lib/sound/sounds.ts` (naOS blips and scans, rate-limited, off until the first click or key press). `nfBuy` has a voice per stat (keypad, relay clack, ticks, chime, airy swell); `nfTierUp` plays the first time a tier is bought, `nfDecrypt` when a stat unlocks, `nfAscend` is the long root-access sequence. The reactor hum is `setHum()` in `lib/sound/engine.ts`, driven every game tick; it rises with Bytes/s, pitches up during an Overclock, and has its own Hum switch in the Menu (`nf-hum-v1`).

## Gotchas
- Always put `font` rules for buttons through `:where(button)` (the reset is), or element selectors beat the class rules.
- Events only spawn once Multipliers plus Reboots reach 5 (the trace needs 8), so a brand-new player is not interrupted. The incoming card waits 15 s, so a Playwright test that fast-forwards a fake clock must step in small chunks and stop as soon as `.nf-ev` exists.

## Goals, secrets, Records and the console (`nf`)
- Goals: seven tiers of six (Access to Zero). Each done goal or found secret gives +2% to everything, a full tier +8%. `state.achAt` holds when each was done (the log shows it). Tiers 6 and 7 cover the deep materials, the tree and long grinds.
- Secrets (`SECRETS` in engine.ts) show as ???? with a clue. Three are unlocked by hidden console commands (`nf ping 127.0.0.1`, `nf sudo`, `nf whoami`), three by play (3 am session, 24 h played, a full standby report).
- Records window (dock and a phone tab): this run, materials, lifetime, progress. Built in `lib/nodefarm/records.ts` (`recordSections`).
- Console: `nf`, `nf stats`, `nf goals`, `nf secrets`, `nf open`. The console asks the open game for its state with an `nf:live` event (the game fills `detail.live`); with no game open it reads and writes the saved game in localStorage. `nfCommand` is pure, so new commands go in records.ts.
- New life counters (`capped`, `peakBps`, `apTotal`) and `achAt` are filled in for old saves by `parseSave`.

## Drones (automation)
One Drone per button tier (T1 to T6), bought with Aether, up to level 10 (`TUNE.drone`). Each level presses that tier's button 0.25 times a second on every stat the player has armed (Armed switch in each stat zone; Reboots are never automated). Drones reset on Ascend, the armed list is kept. Time away runs them at 50% speed and the standby report shows the Drone presses. The Autoloader perk now covers Multipliers and Copper through Chrono (max 9 levels).

## Code reveal (lib/nodefarm/cx.ts, app/camino/nodefarm-cx.css)
One open/close animation for every window, card and pop-up ("terminal print"): the frame opens out of a thin line, corner brackets snap in, a scan line sweeps, rows marked `data-cx-i` print left to right with a caret, top to bottom, and `data-cx-scr` labels decode out of glyphs (the engine's `scrambleNow`, always lands on the real text). Closing deletes rows bottom-up, then folds the frame back to a line. About 280 ms in, 160 ms out, 40 ms per row, at most 8 staggered rows, only rows on screen animate.
- `codeReveal(el, { dir, rows, ms, bare })` returns a Promise; a new call on the same element restarts (never queues); a deadline timer always settles it; reduced motion resolves at once. `cxPlay(el)` replays the open, `cxStop(el)` lands it now, `cxClear(el)` lifts what an "out" left (hidden).
- `useCodeReveal(ref, open)` keeps a thing mounted through its exit.
- `--cx-c` sets the bracket/caret/scan colour (falls back to `--c`, then cyan). `bare` skips the frame for things that sit inline.
- Windows (Map, Goals, Records, Ascend, Menu) go through `closeWin()` in node-farm.tsx; on phones a tab switch prints the section's rows in. Put `data-cx-i` on a panel's sections to control the print order; without any, the pane's second-level children print.
- `data-cx-scr` replaces the text node, so only put it on static labels (use an sr-only twin like WinBar does).
- Where it is used: windows (node-farm.tsx), the offline report (away.tsx, rows tagged, backdrop fades), quick-time event cards (events.tsx: prints in, reprints the body on each stage, deletes out while the last state stays on screen inert), banners (juice.tsx, timing unchanged), tooltips (guide.tsx `Tip`: reprints when the target changes, deletes out on leave), folding zones and the Drone bay (`useFoldReveal`, rows only, first render skipped). The tree card and the Ascend window use it from their own files.
- Sound: `nfPrint` (soft key ticks, one per row) on a framed "in", `nfDelete` on a framed "out"; bare reveals are silent. Pass `sound` to override.
- Three styles, picked game-wide: `print` (default), `decrypt` (rows sit under flickering glyph noise that resolves left to right), `crt` (window switches on like a monitor: line, flash, scanlines; folds and tooltips flicker). Try one with `nf anim decrypt` in the console (saved per browser) or `?cx=crt` in the URL. CRT animates `transform`, so it fits windows that position with `translate`/`left`, not with `transform`.
- Banners sit under an open window (z-index 55 while `body.nf-win-open`) instead of covering it.

## Game feel (components/nodefarm/juice.tsx, app/camino/nodefarm-juice.css)
- The game talks to it with `juice.emit({ t: "press" | "tier" | "unlock" | "ascend" })` and `checkMilestones(s, bps)` (called twice a second from the loop). It never touches the engine or the save.
- Press pop-ups: plain DOM nodes in a fixed layer on `<body>` (no React state), tinted by stat, a few dither sparks, bigger from tier 4 up and on Reboots. Max 14 alive; held-button repeats merge into one pop every 300 ms. They appear over the last pressed `.nf-btn`.
- Banners (one at a time, queued, unlocks jump the queue): first-ever stat decrypt (full, with the stat's role), repeat decrypts and first purchase of a tier (short), and milestones (Bytes/s powers, presses, Reboots, Ascensions). What was already seen is kept per device in `nf-juice-v1`; the first call on a device only records, so returning players get no pile-up. Add milestones to `MS`.
- Ascend: a full-screen sequence on `<body>` that charges a scaled-up reactor core (magenta flicker), flashes once, then types "Root access granted" and counts up the AP. Click, Enter, Esc or Space skips the charge, then closes; it closes itself after 14 s.
- Reduced motion: no pop-ups, scramble, flash or count-up; banners and the Ascend card just appear. Haptics (Android) only after the first tap.
- Class names use the `nf-pop`, `nf-jb` and `nf-rx` prefixes (`nf-asc*` already belongs to the Ascend panel).

## Guidance (next step, locked zones, tooltips, progress map)
- `lib/nodefarm/guide.ts` (pure, reads only the engine): `nextStep` picks the one thing to do now (four TRAINING steps, then the chain zone by zone, Drones, Ascend, spending AP, then the nearest goal), `unlockInfo` says what opens a locked zone and how far along you are, `buttonTip` / `droneTip` build tooltip content from the engine's own `button` and `derive`, so a rebalance in `TUNE` needs no change here. Reboot unlock numbers are `REBOOT_UNLOCK` in the engine.
- `components/nodefarm/guide.tsx`: the always-visible strip under the HUD (title, why, progress bar with ETA, "Show me" opens the zone and scrolls to the glowing button, "Map") and the tooltip layer (`TipCtx`, one `.nf-tip` at the root of `.nf`, positioned from the button's box because quartz buttons are clip-pathed). Hover and keyboard focus on desktop; on touch the tip flashes for 2.6 s after a tap, so an unaffordable button explains itself.
- Glow: `data-guide` on the targeted button, zone, dock button or tab. Only the first locked zone is drawn in full (with a progress meter); the rest fold into one "BEYOND" line, and the Drone bay appears once Aether is open.
- `components/nodefarm/map.tsx`: the Map window (dock button, a tab on phones, MAP in the strip): signal chain Bytes to Chrono with state and boosts, Ascend / Drones / Goals cards, and a summary of the prestige tree sections and a button into the tree menu. Saves are unchanged (nf-save-v1).

## Prestige tree (full-screen menu)
- **40 nodes, 8 per section** (Nate, 2026-11-12: fewer, bigger, unique nodes). Data in `ARMS` in `lib/nodefarm/engine.ts`: each row is slot, id, kind, name, effect (`blurb`), flavour line (`flavor`), effect data (`fx`). Every node does one distinct thing; six switch on whole systems (`fx.feature`, checked with `hasFeature`). The node list Nate can edit lives in his doc "Node Farm prestige tree: new node list".
- Layout: each section is a diamond along its arm (`SLOTS`): entry at 2.4 units, an upper path (slots 1, 3, 5) and a lower path (2, 4, 6), keystone at 9.6 units. No bridges between sections. Spacing is at least 1.87 units between any two nodes. Node fields the menu and art read: `kind` (minor, notable, keystone), `flavor`, `sprite` (= id), `ix` (index in `TREE`), `entry`, `chain` (Carrier I to III, Mounted drive I and II).
- Reveal: `nodeVis(s, n)` gives `shown` (owned or buyable: touches the core or an owned node), `fog` (one step past a shown node: a silhouette, no name or cost) or `hidden`.
- Costs: `SLOT_COST` by slot (4 to 140 AP), notables x1.3, the Rubber duck 1 AP, all scaled by `TUNE.treeCost`. **Respec** (`respec`) is free, refunds every AP and clears the Mounted drives.
- AP bonus: +30% per AP held, so spending AP lowers it until respec (Nate kept this 2026-11-12; `TUNE.apBonusFromEarned` would count spent AP too, but the sim then finishes the tree in 12 to 19 h). Carrier nodes raise the per-AP value (`apEach`). `TUNE.apGainSoft` puts a log knee on Ascends above 250 AP so AP cannot run off to infinity after the tree is done.
- Pacing (sim): first Ascend 3.3 h, whole tree 60.3 h without Drones, 75 h with the bot arming Drones (Nate's target: about 60 h).
- Effects (`treeFx`, cached per tree array): boosts written "xN" multiply with each other (`bytes`, `global`, `reboot`, `mats`, `ap`, `drone`, `ocTime`, `ocX`). The others: `growth` (prices climb slower), `rebootKeep`, `unlockMul`, starting kits (`kitReboot`, `kitProd`, `kitDrones`, applied in `ascend`), `droneKeep`, `droneGlobal`, `mounts`, `eventRate` (`eventHaste`), `winBoost` (`state.runWins`), `zeroDay` and `echo` (returned by `breach`). `treeTotals(s)` turns them into readout rows for the menu.
- Systems: Buy max (`pressMax`, toggle above the stat zones, per device `nf-max-v1`), Watchdog timer (`watchdogStep` in `tick`, switch in the Reboot zone, `state.watchdog`), Forecast (time to afford on each button), Dead drop (`dropFill` / `openDrop`, `state.dropAt`, HUD meter; real time, fills while away), Standing orders (`autoArm`, `state.autoArmed` so a stat you disarm stays off), Mounted drives (`setMount`, `state.mounts`, picker on the Ascend pane), Ghost line, Cross-talk, Echo (the event layer brings the next event right after the result), Zero-day (`payout`).
- Old saves: `parseSave` calls `migrateTree`, which drops ids that are not in the tree and refunds them at their old price (`LEGACY_COST`, the 60 nodes from #157). The refund is shown once in the feed (`state.treeRefund`). Story logs count a section as whole when all 8 of its nodes are owned. The "Whole tree" goal needs all 40. The Rubber duck opens the secret "Quack".
- Menu: `components/nodefarm/tree.tsx` (`TreeMenu`), styles `app/camino/nodefarm-tree.css`. Opened from the Ascend card, the Map, the guide strip, the dock and a phone tab (once you have AP, a node or an Ascend). Portaled to `<body>` inside a `.ctos nf-tm-host` wrapper (z-index 1000) so no page transform can shift it; while open the body gets `nf-win-open nf-tm-open` (hides the site bar and dock). The site's search, map and console scrims (`.nv-scrim`) are lifted to z-index 1003 so they open above the tree, and the tree ignores Escape while one is open.
- Framing (second pass, 2026-11-12): phones get the whole screen with the site bar hidden. Desktop (900 px and up) keeps the site's top-left and top-right clusters (`body.nf-tm-chrome`, `.nv-top` lifted to z-index 1001, styled as when scrolled) and the tree's own bar slots between them on the same line (`--tm-l`, `--tm-r`, `--tm-t`, `--tm-h`, measured from `.nv-start` and `.nv-tools` on open and resize). The view then fills the screen; `dims.st` is how much of its top the bar covers, and fit, focus and the card all keep clear of it. The page dock waits behind a `</> pages` tab at the bottom centre (`body.nf-tm-dock` shows it, the tab rides on top).
- Opening and closing: a boot sequence (`data-boot="in"`, `BOOT_MS` 1.4 s): the layer opens out of a scanline, real terminal lines type over a dark screen that dithers away (`tree --mount`, node counts, AP), the camera starts at 2.3x on the core and pulls back to the fitted view, nodes decrypt ring by ring (`RING`, steps from the core, 70 ms per ring). Any key, click or wheel ends it early. Closing (`close()`, the X and the second Escape) collapses the layer to a line and then a point (`data-boot="out"`, 340 ms) before the game unmounts it. Reduced motion skips both.
- Controls line: a `~/tree $` prompt with a blinking caret and a dithered edge in the bottom-right corner. It reads the controls (and how many nodes are ready) until the first touch, then folds to `~/tree $ help` or `~/tree $ N ready`; clicking it toggles. Status messages (respec refund) use `.nf-tm-toast`. Section labels render under the traces.
- Look (Nate's picks 2026-11-12): nodes are raised bevelled square tiles (stepped box-shadow extrusion in the section colour once owned, a blurred ground shadow, a perspective tilt toward the mouse, lift on hover); notables have a double frame, keystones a breathing bracket halo. Buyable nodes pulse corner brackets. Links are circuit traces (Nate picked 2026-11-12): straight run, 45 degree bend, straight run, with vias at the bends, on a dark bed; reachable traces march, owned ones light up, pulse and carry white packets outward (one `<path>` per section). Sizes: `SZ` (88 / 112 / 152 px), `U` = 165 px per tree unit.
- Reveal: only nodes near what you own are drawn. `nodeVis` from the engine when it exists, else graph distance: owned, core and one step out are readable, two steps out are encrypted silhouettes (sprite state `hidden` plus a ?), the rest is not rendered. Newly revealed nodes play a decrypt pop (`data-new`).
- Camera: `cam` = world point at the view centre plus zoom. `flyTo` eases centre and log-zoom over 560 ms on rAF and feeds every frame to the backdrop (`TreeBackdrop.move`). Picking a node glides to it (node left of centre on desktop, upper third on phone), zooms to at least 1 (0.78 on phone), dims everything not linked to it. Fit frames the readable nodes; the camera is clamped to the drawn ones. A ResizeObserver refits until the player touches the camera. Pan: drag or arrows; zoom: wheel, pinch, +/-; `0` fits; first Esc lets go of the node, the second closes. Hover only counts real mouse movement, so the camera sliding a node under a still cursor never swaps the card.
- Card: one `.nf-tm-card` in screen space next to the node, with a dashed leader line; repositioned on every camera frame. The side is scored: each side that fits is tried and the one covering the least of the other drawn nodes wins (covering its own node counts 6x; right is preferred and the current side is sticky). Rows (`data-cx-i`): `section.kind` label and state chip, the name (scrambles in, always settles), the effect in its own monospace bar with an `fx` tag (`err` for encrypted, `sys` for the core) and numbers highlighted, the flavour line as an italic serif quote block with a dithered edge (Nate's second-pass ask), a `// needs a neighbour` line when locked, cost and Install. It opens and closes with the shared code reveal (`codeReveal` from `lib/nodefarm/cx.ts`); on close it keeps the last node's content (`leaving`) until the rows have deleted. Hover shows it with a short grace period so the mouse can reach the button; tap or click pins it; keyboard focus shows it.
- Checks: `/mnt/project-files/portfolio/node-farm-tree/v3/` (`shots.mjs`, `BOOT=1` adds boot frames; `checks.mjs` for keyboard, Escape, pinch, reduced motion; `chrome.mjs` for the desktop framing, search above the tree and Escape order; `boottrace.mjs` logs the camera through the boot) and `v2/perf.mjs` for drag-pan frame times.
- Art: `scripts/naos-art/nodefarm-tree.py` writes `public/naos/nodefarm/tree-nodes.{png,webp}` (32 px cells, 8 per row, cell = arm x 12 + slot, cell 60 = the core; glyphs are shared between a few nodes but frame, colour and marks differ) and `tree-bg.{png,webp}`. Each section has its own tinted wedge and dither pattern in the CSS. To add a node, add a row to `ARMS` and a glyph entry in the script.
- New art (2026-11-12, art thread; the menu rebuild wires it in):
  - Backdrop: `components/nodefarm/tree-backdrop.tsx` (`TreeBackdrop`, a ref handle with `move(x, y, k)` = the world transform, `resize(w, h)` = the view size, `focus(branch | null)`). Render it as the first child of the pan/zoom view so its box matches the world's. Three tiling layers `tree-bg-0..2` (512 art px, drawn 2x, far to near: deep space with the nebula baked in, coloured stars, near motes) follow the camera at 10, 45 and 85 percent and take 15 to 95 percent of the zoom (Nate picked "strong depth"); the near layer also sways in a slow loop. `TreeDust` (same file) is a dust layer the menu renders after its world, so it passes in front of the nodes at 135 percent of the camera; it follows the backdrop's camera by itself and is hidden under reduced motion; a world layer moves 1:1 with the nodes and holds the core halo (`tree-core`, 800 world px) and one nebula per section (`tree-sec-<branch>`, 1024 world px, centred on the middle of that section's nodes). Idle motion: the star layer drifts sideways and the halo pulses; none of it under reduced motion. Each layer is the view plus one tile; a pan writes only a translate, and the tile size (layer scale) changes only when the zoom crosses a 2 percent step. Below zoom 0.95 the art switches to smooth sampling (`data-soft`) to avoid moire. Art script `scripts/naos-art/nodefarm-tree-bg.py`.
  - Sprites: `components/nodefarm/tree-sprite.tsx` (`TreeSprite`, props `sprite`, `state` = owned / open / locked / hidden, `scale` default 2). One unique shaded pixel icon per node (minor 32, notable 40, keystone and core 64 art px), transparent background, outline and drop shadow baked in; the menu draws the frame. Sheets `tree-spr-{s,m,l}`, one row per sprite, columns: shine frames 0 to 3, locked (two greys), hidden (dark silhouette). Owned nodes shine every 7 s, offset per node. ## Quick-time events
`lib/nodefarm/events.ts` holds the event list and every timing number (`EVENT_TUNE`); `components/nodefarm/events.tsx` is the `EventLayer` that schedules them and draws each one as a centered card over a dim scrim (never in a menu). Flow: incoming card (Engage / Skip, 15 s then it passes, controls lock for 0.65 s so a stray tap can't start one) then the live challenge then a short result card. Four types: Intrusion (four-key memory sequence), Power surge (hold, release in the green band, 3 tries), Signal lock (stop the sweep in the zone, 3 tries), Breach trace (hit 4 of 5 lit nodes on a 3 x 3 grid). Winning calls `breach()` (the timed Overclock); missing or skipping costs nothing. All of them work with touch, mouse and keyboard (1 to 4, 1 to 9, Space, Escape skips), the card is an `alertdialog` and returns focus when it closes. Events can be switched off from the card or the Menu (`nf-events-v1` in localStorage). To add a type: add it to `EVENTS`, add a body component in `events.tsx`, and style it under `.nf-ev`.

## Scenery (dither backdrops per era)
- Art: `scripts/naos-art/nodefarm-scenes.py` draws nine original 480 x 270 landscapes plus an Ascend piece into `public/naos/nodefarm/scene-<n>.{png,webp}` (`scene-ascend` for Ascend). Two-tone palette PNGs (era colour at 55% for the dither, full colour for lit lines), about 1 to 6 KB each. Every scene tiles sideways without a seam, so a wide board repeats it. Rebuild with `python3 scripts/naos-art/nodefarm-scenes.py` (or `... 3 ascend`).
- Eras (`lib/nodefarm/scenery.ts`, `eraOf`): the furthest stat the current run has opened. 0 Uplink (Bytes, Multipliers, cyan), 1 Foundry (Reboots, Copper), 2 Wafer (Silicon), 3 Lattice (Quartz), 4 Aurora (Aether), 5 Monolith (Runes), 6 Glass (Starglass), 7 Eclipse (Voidsteel), 8 Clockwork (Chrono). After an Ascend it steps back until the stats reopen.
- Where it shows (`components/nodefarm/scenery.tsx`, `app/camino/nodefarm-scenery.css`): the ground (a viewport-tall sticky stage behind the board, `z-index: -1`, so it shows in the gutters and margins only; panels stay solid), a framed scene window under the log in the core rail, an art banner on the Ascend pane, and behind the standby report and the Ascend sequence under a dark veil. `data-era` maps to the image through the `--scn` custom property, one place for all surfaces. Changing era crossfades the ground in steps; reduced motion swaps instantly.
- Scene window: shows a different piece from the backdrop, a 360 x 144 close-up per era (`detail-<n>`, `dN` in the script: server rack, crucible, die, crystal, scope, monolith, gem, eclipse limb, gears), so the rail does not repeat the wide scene.
- Cost: only the current era's image loads (CSS background), no JS per frame, no canvas. To add an era, add a function to `nodefarm-scenes.py` and a row to `ERAS` and the `[data-era]` list.

## Code theming (terminal feed)
- `lib/nodefarm/feed.ts` (pure): lines are tokens (`id` in the stat's colour, `fn` cyan, `num` amber, `str` green, `kw` purple, `p` dim punctuation, `c` comment). `FeedStore` keeps the last 60 lines and tells the UI at most every 150 ms. `batch(key, mk, amount)` counts repeats (same button, or Drone presses) into one line that updates in place, looking back four lines so two alternating streams each keep one line.
- `components/nodefarm/feed.tsx`: the log under the reactor (8 rows). Only the newest line animates: lines flagged `type` (unlocks, goals, secrets, reboot, ascend, greeting) are typed out two characters at a time with a blinking caret (the timer always finishes; reduced motion skips it); batched lines get a short scan-in. `role="log"` with `aria-live="off"` so batched updates do not spam a screen reader.
- The game loop counts presses nobody clicked as `life.presses - last - manual` and batches them into `drones.sweep() ×N`. Plain text from the game still works through `log(text, tone)`; `fromText` adds an `ok:` / `warn:` / `alert:` / `sys:` tag and picks out numbers and CAPS.
- Button captions (`fnCaption`: `.add(5)`, `.spawn(125)`, `.reboot(1)`) and the locked-zone `if (mul >= 5) copper.decrypt()` line are decoration only (`aria-hidden`); names and numbers on buttons are unchanged. Styles: `app/camino/nodefarm-code.css`.
- To add a feed line from the game: `feedStore.push(tokens, { tone, type })` with `call(id(stat), "name", [args])`.

## Story logs (lore)

Premise (Nate picked "inherited node", 2026-11-12): you took over node-01 from a previous operator who left logs. `lib/nodefarm/story.ts` holds the 25 logs, each with a test on the game state (stat unlocked, reboot count, tree branch finished, goal rank, and so on). Numbers follow writing order, so early finds leave gaps. A log is stored in `State.logs` the first time its test passes (checked in the tick, `node-farm.tsx`) and is kept through Ascend. A save from before logs existed gets them all at once, with one quiet feed line.

Where they show: a typed `logs.recover("004")` feed line and a milestone banner when one is found, the "Operator logs" list in the Records window, `nf logs` and `nf logs <number>` in the console, and one operator line on the Ascend screen (`ASCEND_NOTES`). The Ascend notes quote log numbers 012 and 017, so keep those in step if the order of `LOGS` changes. To add a log, append to the end of `LOGS` (inserting renumbers every later log).
